# Plan: Script the gstack fork sync up to the merge decision

One Python 3 script (stdlib only, the same as `forge-pr`) runs the sync as numbered stages. It records progress in a run directory, so a re-run after a fix resumes at the first stage that hasn't passed. It never touches the live checkout's branch or working tree; all git work happens in worktrees under the run directory.

## Files that change

| File | What |
|---|---|
| `.forgejo/scripts/fork-sync` | New. Executable Python 3 (`#!/usr/bin/env python3`), stdlib only. CLI and stages. |
| `.forgejo/scripts/fork_sync_lib.py` | New. Pure logic with no subprocess calls, so it can be unit-tested: free-runner log parsing, failure classification, fork-delta comparison, hooks manifest diff, report rendering, stage state. |
| `.forgejo/scripts/test_fork_sync.py` | New. `unittest` suite: unit tests on the lib, plus integration tests that build throwaway git repos (bare `origin`, bare `github`, a clone) for the conflict-stops-before-push case and resume. |
| `.forgejo/scripts/README.md` | New. Usage, stages, stop conditions, exit codes, and how to resume. |
| `docs/changes/2026-10-26-fork-sync/plan.md` | This file; `## Deviations` added if the build departs from it. |

Nothing under upstream's paths changes, so future syncs cannot conflict on this work. `.forgejo/` is skipped by the egress scanner (dot-directory); the intent records that.

## Design

**CLI.** `fork-sync [--repo PATH] [--until STAGE] [--reruns N] [--run-dir PATH]`

- `--repo` defaults to the git toplevel of the current directory, which must have remotes `origin` (forge) and `github` (upstream).
- `--until merge|checks|suite|codex|pr` (default `pr`). `--until checks` is the dry run: pre-flight through build checks, with no suite, Codex or push.
- `--reruns` defaults to 3.
- `--run-dir` defaults to `~/.gstack-dev/fork-sync/v<upstream VERSION>/`.

**Exit codes.** 0 means the PR was opened or the `--until` stage passed. 10 means stopped on a problem (the report says what; the worktree is kept). 2 means usage or environment error. 3 means another run holds the lock.

**Run directory.** It holds `state.json` (stage → passed, plus the SHA it passed at), `report.md`, `logs/`, `hooks-backup/` with `hooks.sha256`, and the worktrees `merge/` (branch `upgrade/sync-v<VER>`), `upstream/` (detached at `github/main`) and `baseline/` (detached at the pre-sync `origin/main`). A `lock` file uses `O_EXCL` and holds the PID; a lock left by a dead PID is reported, never stolen silently.

**Stages,** each idempotent, recorded in `state.json` when it passes:

1. `preflight`: `git fetch origin` and `git fetch github main`. Stop unless forge `main` equals the GitHub mirror's `main` (`git ls-remote`; the mirror URL is read from `--mirror` or the `FORK_SYNC_MIRROR` env var, default `https://github.com/Jmeg8r/gstack.git`). Stop if `github/main` is already an ancestor of `origin/main` ("nothing to sync"). Record the live checkout's HEAD, branch and the sha256 of `git status --porcelain` for the final check.
2. `hooks-backup`: resolve `git config --global --get core.hooksPath`; if it's set, copy that directory to `hooks-backup/` and write per-file sha256. If it's unset, record "none" and skip the hooks checks.
3. `merge`: create the `merge/` worktree off `origin/main` on `upgrade/sync-v<VER>`, or reuse it if it exists. Then `git merge --no-ff --no-edit github/main`. On conflicts, list the paths (`--diff-filter=U`) in the report and stop with code 10. On resume, the stage passes once `MERGE_HEAD` is absent, the tree is clean, and `github/main` is an ancestor of HEAD; a merge someone else finished by hand counts.
4. `fork-delta`: take the fork's pre-sync delta, the files that differ between `merge-base(origin/main, github/main)` and `origin/main`. Every one of them must still differ from `github/main` after the merge; a fork file that now matches upstream is a silently dropped fork change. Also report the upstream commits since the base that touch fork-delta files (`git log base..github/main -- <files>`) as "review these". A dropped file stops the run.
5. `checks`: in `merge/`, run `bun install`, `bun run build:cso` and `bun run gen:skill-docs`, then require `git status --porcelain --untracked-files=no` to be empty (no generated drift). Then `bun run typecheck`, and `bun run typecheck:test` with output containing `none new`. Any failure stops the run.
6. `suite`: run `bun run test --verbose` in `merge/` (logged). Parse `  ✗ <file> — <test>` and `  ✗ <file> (crashed: …)` lines into the set of files with failures. A clean suite skips to Codex. Otherwise create `upstream/` and `baseline/`, each with `bun install` and `build:cso`, and run every failing file alone (`bun test <file>`, 600 s timeout) in all three worktrees. Then, for files where `merge/` has failures that `upstream/` doesn't, rerun `--reruns` more times in each worktree. A test name, normalized (timings and `/private/...` paths stripped), is classified:
   - **fork-caused**: fails in every `merge/` run and in no `upstream/` run, and in no `baseline/` run. This blocks.
   - **pre-existing on fork**: same, but it also fails in `baseline/`. Reported, not blocking. This is what keeps the `review-pr.sh` egress-scanner finding from blocking every run.
   - **flaky**: fails in some `merge/` runs but not all, or in some `upstream/` runs. Reported, not blocking.
   - **upstream/environmental**: fails in `upstream/` every time. Reported as a count.
   - The hooks check runs after this stage, because the suite is what wrote to `~/.git-hooks` before #3353.
7. `codex`: in `merge/`, run the installed `/codex` review path exactly as `~/.claude/skills/gstack/codex/sections/review-mode.md` does (`gstack-review-log --start`, then `gstack-codex-probe select-model review` and `run-with-timeout ... 330 codex review --base github/main` with the read-only sandbox config). The verdict comes from `bun lib/outside-review-result.ts --verdict --exit <code> --stderr <file> structured <out>`. Exit 0 or 4 (clean or unverified) passes. Exit 3 (findings, P0/P1) or 1 (unavailable) stops. Log the result with `gstack-review-log --finish`. The raw output is saved for the PR comment.
8. `hooks-verify`: re-hash the hooks dir against `hooks.sha256`. Any difference stops the run, shows the diff, and gives the restore command. It never restores automatically.
9. `pr`: `git push -u origin upgrade/sync-v<VER>` (never `--force`, never `main`). Then `forge-pr --repo <owner/name> create --base main --head <branch> --title "chore(upstream): sync fork to garrytan/gstack v<VER>" --body-file report.md`. Post the Codex comment (verbatim output in a `codex-review` fence plus an explicit `GATE: PASS|UNVERIFIED`) through `forge-pr`'s `ForgeAPI`, loaded the way this session did, so the token stays in `forge-pr`'s own reader. Afterwards, check that the mirror's `main` is unchanged and that the live checkout's HEAD, branch and status hash match the values recorded at pre-flight.

**Report** (`report.md`, also the PR body): versions and SHAs, the merge result, the fork-delta table and "review these" commits, build check results, suite classification counts plus a fork-caused/pre-existing/flaky table, the Codex verdict line, the hooks check, and the forge ai-review size-limit note. It ends with the post-merge steps (discard the `name:` lines, fast-forward the live checkout, `./setup --prefix`).

## Order of work

1. `fork_sync_lib.py` with its unit tests first (test-first: classification, log parsing, delta, hooks diff, state).
2. `fork-sync` stages 1 to 5, plus the integration tests: conflict stops before push, with the remote unchanged by `git ls-remote`; resume after a hand-resolved merge; a dropped fork file stops the run.
3. Stages 6 to 9.
4. README.
5. Dry run against the live fork: `--until checks`.
6. Commit per logical unit, push `feat/fork-sync`, open the forge PR, run the Codex review.

## Risks

- **The free suite still writes outside the hermetic home** (it did before #3353). Mitigated by the hooks backup and verify stage, which stops without restoring, so James sees it.
- **Free-runner output format drift** upstream breaks the parser. Mitigated: the parser fails closed. If the runner's summary reports failures but no `✗` lines parse, the stage stops with "could not attribute failures" instead of reporting clean.
- **Standalone reruns are slow:** about 25 to 45 minutes for 90 files across three worktrees. Accepted; documented in the README. The script is long-running, so the README says to launch it under `bin/gstack-detach` when an agent runs it.
- **The Codex review path changes upstream.** The script reads `review-mode.md` only for documentation and calls the probe binaries directly. A changed CLI fails at the probe step with its own error, not silently.
- **No egress receipts** for the push, PR and comment. This is fork-operator tooling outside gstack's shipped surface, and the intent records that the scanner doesn't read `.forgejo/`.

## Proof

- `python3 -m unittest discover -s .forgejo/scripts -p 'test_*.py' -v` → all pass. This includes `test_conflict_stops_before_push` (exit 10, conflicting path in `report.md`, `git ls-remote origin` unchanged) and `test_dropped_fork_file_stops`.
- Positive control: deleting the conflict check in `stage_merge` makes `test_conflict_stops_before_push` fail.
- `.forgejo/scripts/fork-sync --until checks` against the live fork (upstream at 1.91.248.0 or later) exits 0 and prints a `report.md` with the merge, delta and build results. `git -C /Volumes/Projects/Repositories/gstack status --porcelain` and its branch are unchanged afterwards, and forge `main` and the mirror are unchanged (`git ls-remote`).
- `~/.git-hooks` sha256 matches before and after the dry run.
- Codex review of `feat/fork-sync` (`--base origin/main`) is posted on its forge PR.

## Options not taken

- **A gstack skill instead of a script.** A skill would make an agent re-derive the steps every time, the cost being automated away, and would live in upstream-owned paths.
- **Bash.** The classification and report logic needs real data structures and unit tests; Python matches `forge-pr`.
- **Opening a draft PR on problems.** James chose stop-before-push.
- **Auto-restoring `~/.git-hooks`.** Restoring hides that something wrote there; stopping surfaces it.
- **Scheduling it (launchd).** Out of scope per the intent.

## Deviations

- **`--accept-dropped PATH`** (new option). The fork-delta stage would otherwise stop forever on a deliberate drop, like PR #16's removal of the fork's gate when upstream shipped its own. A drop not named this way still stops the run; a named one is listed in the report as dropped on purpose.
- **Fork-delta "adopted" class.** A fork-changed file that matches upstream because upstream took the fork's exact bytes is reported as adopted, not dropped. The plan's "every fork file must still differ from upstream" would have stopped on it falsely.
- **Head-bound stage freshness.** Every stage from `merge` on records the merge worktree's HEAD it passed at, and is re-run when HEAD differs. A fix committed during a stop therefore re-runs `fork-delta`, `checks`, `suite` and `codex` instead of trusting stale passes.
- **Default run directory resumes the unfinished run.** Without `--run-dir`, the script resumes the single unfinished run if there is one, rather than keying only on the current upstream version. An upstream release landing mid-fix would otherwise start a second sync. More than one unfinished run is a usage error.
- **`--until fork-delta`** added to the stage choices, for the integration tests and for checking a hand-resolved merge without running the build.
- **Hooks checked twice:** right after the suite (recorded in the suite section), and as its own stage before the push.
- **Codex review hardening (forge PR #18, passes 1 to 4).** The suite stage now fails closed on the runner's own incompleteness markers, on unfinished standalone reruns (a timeout, no `Ran N tests` line, more than one file executed), and on failures no named test accounts for. Home-containment diagnostics and unattributed lines block unless `--accept-unaccounted` (new option), and are listed in the report. Files absent from a comparison tree are judged against the tree that has them, and failures no standalone run reproduces stay in the inventory as `not-reproduced`. Reruns use exact absolute selectors. The merge worktree must be clean before every stage from `fork-delta` on and before the push. `hooks-verify` is never cached and also runs right before each push. A resumed preflight stop re-reads the remotes, `--run-dir` is resolved to an absolute path, a completed push is recorded and reported, and a resumed run refreshes the existing PR body.
- **`bun --no-env-file` on every bun subprocess, but not `--config=/dev/null`.** The repo's committed `bunfig.toml` preloads `test-setup.ts`, the configuration CI tests with, so it is kept on purpose; a modified `bunfig.toml` is caught by the dirty check. AGENTS.md's full isolation rule targets gstack running inside an audited repo, not the fork's own test suite.
- **Re-plan of the `suite` stage (2026-10-26, approved by James): structured runner results replace stream parsing.** Running the stream parser over the real suite logs of forge PRs #16 and #17 showed that the `--verbose` stream also carries the runner's own self-test output: nested `⚠ FLAKY`, `[test:free] FAIL —` and shard lines with fixture names. No pattern can tell the real runner's lines from a nested test's. Seven Codex passes kept finding stream edge cases for that reason, and a separate review panel in the fork session independently found the same false-green. The stage now uses the runner's CI mode, which its own CI uses:
  1. `bun run scripts/test-free-shards.ts --ci-plan <run>/ci/plan.json --shards <N>` (`--shards`, default 6). The plan is bound to the merge HEAD and the exact free-file set.
  2. `--ci-run plan.json --shard i --result <run>/ci/results/<i>.json` for every planned shard: the non-exclusive shards concurrently, then any shard made only of `TREE_MUTATING` files alone. `TREE_MUTATING` is read from the runner's own export; if it cannot be read, the stage stops rather than guess. Each shard runs in its own process group under an outer timeout. `GSTACK_FREE_RETRY_FLAKY` stays unset; the paired comparison is the flake filter.
  3. `--ci-verify plan.json --results <run>/ci/results/`. Exit 0 means every planned shard has a complete, passing result covering exactly its planned files, and the suite stage passes.
  4. Otherwise each result JSON is assessed (`assess_ci_results`). Any missing, duplicate or foreign result (plan id or revision mismatch), an incomplete summary (`filesRan` ≠ planned files, no terminal summary, no `testsRan`), or a `timed-out` shard stops the run outright. Shards with `unattributedFailures` > 0, or `failed` with no failing file and no unattributed count (for example a home-containment failure, whose reason the JSON does not carry), are **unaccounted**: they stop unless `--accept-unaccounted`. The union of `failingFiles` then goes to the unchanged paired comparison on merge, upstream and the pre-sync fork, and `outcome.failures` supplies the test names for the not-reproduced inventory.
  The stream parsers (`parse_free_log`, `suite_completed` and their marker patterns) are removed. `parse_bun_run` stays for the standalone reruns: one file, one process, with no nested-runner ambiguity worth its own parser.
- **Suite bar on a machine where the runner cannot certify its own suite (2026-10-27, chosen by James: compare with upstream).** The first real run of the CI-mode stage against the live fork (upstream v1.91.259.0) stopped correctly: the runner's own `--ci-verify` rejected 5 of 7 shards for incomplete execution summaries. On this Mac the runner's classifier takes a nested run's last `Ran N tests across 1 file` line as the shard's summary (`filesRan: 1` for a 227-file shard), or sees none at all. Under the strict rule no sync could finish here. The stage now:
  1. Treats an **incomplete or timed-out** shard as a coverage gap rather than a hard stop. It then runs the same CI plan in the pure-upstream worktree, after the merge run, never at the same time. A merge shard's gap is **environmental** only when the shard with the same file set is also incomplete or timed out upstream; otherwise the run stops. If the two plans' shard file sets differ (for example because the fork added a test file), shard comparison is impossible and the run stops. Missing, duplicate or foreign results stay hard stops.
  2. Whenever `--ci-verify` does not pass, reruns a **focused set** alone in all three trees, with the same reruns and classification as failing files: every `*.test.ts` the fork changed, plus every test file whose source names a fork-changed source file (by its path without extension). Excluded as triggers: `docs/`, `.forgejo/`. Focused files classified `fork-caused` block, so the fork's own code gets real coverage even inside shards with no usable summary.
  3. Lists every environmental gap, with its shard and file count, in the report.
  4. When `--ci-verify` passes on the merge, the stage passes at once: every shard is complete and green, so standalone reruns would add nothing. The focused set runs only when the full suite cannot vouch for itself.
  5. The focused set is intersected with the runner's free-file plan, so paid E2E files (for example `skill-e2e-*`), which the free plan excludes, never run. Measured on the current fork delta: 19 fork-changed files give 101 focused test files.
- **Untruncated home-change window (2026-10-27).** The second real run stopped at the suite stage because the runner caps its containment path list at 10 (`+164 more`). The visible paths were all `~/.claude/.git/*`: a fetch at 21:53 and a `.git/config` write at 21:56 during the run, with no reflog entry, from outside the test sandbox. fork-sync now snapshots the runner's watched home surfaces itself (`home_snapshot`, mirroring `FREE_HOME_SURFACES` and `FREE_HOME_VOLATILE`) before and after each CI run. A truncated containment line is environmental only when every path in that full window matches the external-writer list; otherwise the report names the outside paths. `~/.claude/.git/*` (the config repo's own sync) joins the default external writers. The window is written to `ci-<tree>/home-changes.txt`.
- **Unaccounted shards are compared with upstream too (2026-10-27), applying James's "compare with upstream" bar to unexplained failures.** The third real run stopped on three unaccounted shards. One was a cleanup failure of another kind ("browser child ownership is unconfirmed"). Two were real-home writes: James's memory-sweeper job, and `~/.gstack/slug-cache/<merge worktree path>`, a gstack test writing into the real home while concurrent shards share it. Like a coverage gap, an unaccounted merge shard is now environmental only if the shard with the same file set is also unaccounted or has a gap on pure upstream; otherwise it stops, unless `--accept-unaccounted`. The upstream control run starts when the merge has gaps or unaccounted shards. `~/.claude/memory-sweeper/*` joins the default external writers, because its timing is random and an upstream comparison could not match it reliably.
- **Pre-create the runner's log directory (2026-10-27).** The fourth real run lost shard 2 entirely: the runner creates `.context/free-test-logs` check-then-`mkdir`, so six `--ci-run` processes starting together in one worktree raced, and the loser died with `EEXIST` before writing a result. Upstream CI never hits this, because each shard runs on its own machine. fork-sync now creates both directories (mode 0700, never through a link, as the runner requires) before launching any shard.
- **A timed-out standalone run is a failing observation, not a stop (2026-10-27).** The fifth real run cleared every shard check and the upstream control, then stopped on one focused rerun: `test/ship-skip-actor.test.ts` failed a test, then hung until the 600 s per-file timeout. Run alone, the same file hangs on pure upstream as well. The old rule (a timeout cannot be classified) still holds against reading it as clean, but it does not require a stop. A timed-out run now counts as failing: the failures it named before the hang, plus `<file> :: <timed out>`. Classification then compares it with upstream like any failure, so a hang on both trees is `upstream` and a merge-only hang is `fork-caused`. A failing exit with no `Ran N tests` line, and a selector that matched more than one file, still stop.
- **James's session-log hooks are external writers (2026-10-27).** The resumed fifth run stopped on merge shards 1 and 2: the containment check saw `~/.claude/session-logs/.lock`, `index/sessions.db-shm` and `state.json` change. Those are written by `~/.claude/hooks/end-session-capture.sh` and `session-log-archive.sh` whenever another Claude session ends. The upstream window shows the same writes (9 paths), but they hit different shards, so the shard comparison could not match them. As with memory-sweeper, the timing is random, so `~/.claude/session-logs/*` joins the default external writers.
- **Codex pass 8 findings (2026-10-27; verdict clean, three P2s, all fixed).**
  1. *Standalone reruns use the runner's own flags.* fork-sync ran `bun test <file>` with bun's 5 s default per-test timeout, while the runner's shards run with `--timeout=30000 --max-concurrency=1`. That alone can produce failures the suite never had, or mask a real one when the control times out first. `test/ship-skip-actor.test.ts` failing at 5000 ms in run 5 is consistent with it. Each rerun now asks the tree's own `buildShardArgs([file])` for its arguments (exact selector included), as the shards do, and stops if the answer is not a `test` argument list.
  2. *An interrupt reaps every launched group before the lock goes.* Shards and commands run in their own sessions, so an operator's Ctrl-C never reaches them, and `main()` releases the run lock on the way out. A resume could then start a second suite over live workers. Any exception now kills and reaps every group fork-sync launched before it propagates, and SIGTERM is handled the same way as Ctrl-C.
  3. *A resume archives the previous attempt's CI evidence.* `run_ci` deleted `ci-<tree>/` and `logs/ci-<tree>/` before replanning, destroying the original failure (AGENTS.md: preserve the original failure). They are now moved to `attempt-<n>/` under the same parent before the new attempt starts, and only the current attempt is verified.
- **Codex pass 9 finding (2026-10-27; verdict clean, one P2, fixed).** The Codex review launch was the one command path left outside the pass 8 reaping. `subprocess.run` with an outer timeout kills only the probe, not Codex or its watchdog, and the probe was not in its own group. A SIGTERM or the outer timeout could therefore release the lock while a paid review kept writing `codex.out`. The review now runs through `run_to_files`, which starts the command in its own group and reaps that group on interrupt or on the outer timeout. A timeout reaches the verdict validator as exit 124 instead of crashing the stage.
- **Codex pass 10 findings (2026-10-27; verdict clean, two P2s, both fixed).**
  1. *Kill nested process groups too.* When `gtimeout` or GNU `timeout` is installed (it is on this Mac, from Homebrew), `gstack-codex-probe` runs Codex under it, and the wrapper moves itself into a new process group. Signalling only our own group left the wrapper and Codex running. `kill_group` now snapshots the launched process's descendants (`ps -axo pid=,ppid=,pgid=`) before signalling, and sends SIGTERM, then SIGKILL, to every process group among them. The snapshot is taken first because SIGTERM reparents survivors and breaks the tree. A regression test runs the real `gtimeout` path when it is installed.
  2. *Archive the previous Codex attempt.* A resumed review reopened `logs/codex.out` and `codex.err` for writing and replaced the state's verdict, destroying the earlier review. Before a new review, those files and the previous `state.codex` entry (as `codex-state.json`) move to `attempts/<n>/`, through the same helper the suite stage uses.
- **Codex pass 11 findings (2026-10-27; verdict clean, two P2s, both fixed).**
  1. *Snapshot directory symlinks as links.* `home_snapshot` recorded a symlink to a directory (for example `~/.claude/skills/gstack`, a symlink on this Mac) as `dir`. A test that replaced or repointed it could therefore pass the full-window check behind a truncated containment line. Links, to directories or to files, are now recorded as the runner records them, `link:<target>:<mtime>` from `lstat` and `readlink`, and are never traversed. A surface root that is itself a link is recorded the same way.
  2. *Adopt an existing PR before creating one.* If the forge created the PR but its response was lost, or the run was interrupted before `pr_url` was saved, every resume would call `forge-pr create` again and fail on the PR that already exists. Before creating, the PR stage now looks up the open PRs for the pinned head branch into `main`. When there is exactly one, it adopts its URL and refreshes its body. More than one stops the run.
